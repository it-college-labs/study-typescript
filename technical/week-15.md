### **📚 Конспект для студентов: Продвинутые паттерны и тестирование типов**

**Цель:** Научиться создавать сложные типы с помощью `infer` и проверять корректность типизации в своих проектах.

#### **1. Зачем тестировать типы?**

Представьте, что у вас есть функция, и вы хотите быть уверены, что она всегда принимает аргумент определённой формы и всегда возвращает значение конкретного типа, даже если внутренняя логика усложнится. Обычные тесты (Vitest) проверяют это во время выполнения кода. Тесты типов проверяют это на этапе компиляции, то есть до запуска программы. Это более высокий уровень надёжности.

#### **2. Условные типы (Conditional Types) – повторение**

Это типы, которые могут меняться в зависимости от условия. Синтаксис: `T extends U ? X : Y`.

```typescript
// Пример: тип, который превращает null/undefined в never, а другие оставляет как есть
type NonNullable<T> = T extends null | undefined ? never : T;

let value: NonNullable<string | null>; // Тип value - только string, null отброшен
```

#### **3. Волшебное слово infer**

`infer` позволяет вывести и захватить тип из другого типа внутри условной конструкции. Его можно использовать только в "истинной" ветке (`?`) условного типа.

Базовый паттерн:

```typescript
type Пример<T> = T extends (какой-то_паттерн с infer R) ? R : никогда;
```

#### **4. Классические примеры использования infer**

Давайте "распакуем" сложные типы.

**Получить тип элемента массива:**

```typescript
type ArrayElement<T> = T extends (infer U)[] ? U : never;
```

Если `T` является массивом каких-то элементов (`U`), тип возвращает тип этих элементов (`U`).

**Получить тип, который возвращает функция:**

```typescript
type OurReturnType<T> = T extends (...args: any) => infer R ? R : never;
```

Если `T` является функцией, возвращающей какой-то тип `R`, тип возвращает этот тип `R`.

**Получить тип значения внутри Promise:**

```typescript
type Awaited<T> = T extends Promise<infer U> ? U : never;
```

Если `T` является `Promise` какого-то типа `U`, тип возвращает этот внутренний тип `U`.

Попробуйте в уме:

Чему будет равен `ArrayElement<string[]>`? Ответ: `string`.

Чему будет равен `OurReturnType<() => number>`? Ответ: `number`.

Чему будет равен `Awaited<Promise<boolean>>`? Ответ: `boolean`.

#### **5. Как тестировать типы на практике?**

Есть два основных подхода.

**1. Директива `@ts-expect-error` (встроена в TypeScript)**

```typescript
// Проверяем, что НЕправильный вызов вызывает ошибку типов
function add(a: number, b: number): number {
  return a + b;
}

// @ts-expect-error - следующий код ДОЛЖЕН вызывать ошибку компиляции
add('строка', 5); // Хорошо: компилятор здесь ругнётся, и директива это "ожидает"
```

Если ошибки не будет, компилятор сам сообщит о проблеме с `@ts-expect-error`.

**Плюсы:** Просто, не требует сторонних библиотек.

**Минусы:** Проверяет только наличие ошибки, а не соответствие типов.

**2. Использование `expectTypeOf` из Vitest (предпочтительно для проектов)**

```typescript
import { expectTypeOf } from 'vitest';

function greet(name: string): string {
  return `Hello, ${name}`;
}

// Тестируем тип возвращаемого значения
expectTypeOf(greet).returns.toBeString(); // Проверяет, что greet возвращает string
// expectTypeOf(greet).parameters.toMatchTypeOf<[string]>(); // Проверяет типы аргументов
```

**Плюсы:** Мощный и выразительный API, можно проверять аргументы, возвращаемые значения, свойства объектов.

**Минусы:** Требует наличия Vitest в проекте.

#### **6. Контрольное задание К15.1**

**Часть 1. Создание типа с infer**

Создайте новый файл для утилитарных типов (например, `src/type-utils.ts`). Объявите в нём условный тип `ExtractArrayType<T>`. Этот тип должен проверять, является ли `T` массивом. Если да — возвращать тип его элементов. Если нет — возвращать `never`.

**Часть 2. Тестирование типов в вашем проекте**

Выберите 1-2 ключевые функции из вашего финального проекта (например, функцию из `FinanceManager.ts`). Напишите для них тесты типов, используя либо `@ts-expect-error`, либо `expectTypeOf` (рекомендуется, если у вас настроен Vitest).

**Что проверить?** Соответствие типов аргументов и возвращаемого значения.

**Пример с `expectTypeOf`:** Убедитесь, что функция `calculateBalance` возвращает `number`.

**Пример с `@ts-expect-error`:** Убедитесь, что функция `addTransaction` не принимает объект без обязательного поля `amount`.

**Что должно получиться:**

Новый утилитарный тип `ExtractArrayType` в вашем коде. Несколько строк тестов типов, проверяющих ваши бизнес-функции. Уверенность в том, что ваша типизация работает корректно.

Для работы с `expectTypeOf` убедитесь, что у вас установлен `vitest` и в `tsconfig.json` добавлен `"types": ["vitest/globals"]` или используется импорт, как в примере выше.
