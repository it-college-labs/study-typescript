### **Конспект для студентов: TypeScript – Первые шаги**

**Цель:** Понять основы статической типизации, научиться описывать типы данных и скомпилировать свой первый TypeScript-код.

#### 1. Зачем нужен TypeScript?
JavaScript — язык со **динамической типизацией**. Тип переменной (`string`, `number` и т.д.) определяется в момент выполнения. Это гибко, но часто приводит к ошибкам, которые сложно отловить.

**TypeScript (TS)** — это **надмножество JavaScript**, которое добавляет в него **статическую типизацию**. Это значит, что типы проверяются в момент написания кода (на этапе компиляции), а не запуска.

**Преимущества TypeScript:**
*   **Надёжность:** Компилятор находит опечатки, вызовы функций с неправильными аргументами, обращение к несуществующим свойствам объектов — прямо в редакторе кода.
*   **Читаемость:** Типы служат отличной документацией. Глядя на сигнатуру функции, сразу понятно, что она принимает и что возвращает.
*   **Продвинутые инструменты:** Редакторы кода (VSCode, WebStorm, zed) используют информацию о типах для умного автодополнения, навигации по коду и безопасного рефакторинга.

#### 2. Инструменты: от `tsc` до современных сборщиков
Чтобы выполнить TypeScript-код, его нужно **скомпилировать** (преобразовать) в обычный JavaScript. За это отвечает компилятор **`tsc`** (TypeScript Compiler).

Однако в реальных проектах `tsc` редко используется в одиночку. Чаще его интегрируют в **сборщики (bundlers)**, которые объединяют множество файлов в один (или несколько) бандл.
*   **`tsc`** — основа. Выполняет проверку типов и преобразует `.ts` → `.js`.
*   **Vite** — **современный стандарт**. Невероятно быстрый. Под капотом использует `tsc` для проверки типов, а для транспиляции (преобразования кода) — более быстрые инструменты (esbuild). С него и стоит начинать.
*   **Webpack** — мощный и гибкий сборщик, но с более сложной конфигурацией. Многие старые проекты всё ещё используют его.
*   **Bun** — это не только сборщик, но и альтернативная среда выполнения (как Node.js). Его ключевая особенность — он может **исполнять `.ts`-файлы напрямую**, без явной компиляции, но для финальной сборки проекта всё равно использует `tsc` или другие транспайлеры.

**Установка TypeScript:**
```bash
# Глобальная установка (удобно для экспериментов)
npm install -g typescript

# Локальная установка в проект (рекомендуется)
npm install --save-dev typescript
```

#### 3. Базовые типы и аннотации
Аннотация типа — это указание типа для переменной, параметра функции или её возвращаемого значения.

**Синтаксис:** `let variableName: type = value;`

| Тип | Описание | Пример |
| :--- | :--- | :--- |
| `string` | Текстовые данные | `let name: string = 'Анна';` |
| `number` | Числа (целые, дробные) | `let age: number = 30;`, `let pi: number = 3.14;` |
| `boolean` | Логическое значение `true`/`false` | `let isDone: boolean = false;` |
| `null` / `undefined` | Примитивы, обозначающие отсутствие значения. | `let u: undefined = undefined;`, `let n: null = null;` |
| `any` | **Отключает проверку типов.** Переменная может иметь любой тип. **Старайтесь избегать.** | `let flexible: any = 4; flexible = 'можно строку'; // OK` |
| `unknown` | Тип для значений, чей тип неизвестен на этапе написания кода. **Безопаснее, чем `any`**, т.к. с ним нельзя выполнять произвольные операции без проверки типа. | `let input: unknown = getUserInput(); // Без проверки типов не сработает: input.toUpperCase()` |

#### 4. Массивы, Кортежи (Tuples) и Вывод типов
**Массивы** типизируются с указанием типа элементов.
```typescript
let list: number[] = [1, 2, 3];
// или альтернативный синтаксис:
let alternativeList: Array<number> = [1, 2, 3];
```

**Кортежи (Tuples)** — массивы фиксированной длины с известным типом каждого элемента.
```typescript
let userInfo: [string, number] = ['Алексей', 28]; // ОК
userInfo = [28, 'Алексей']; // Ошибка: несоответствие типов
```

**Вывод типов (Type Inference)** — мощная особенность TS. Компилятор **сам определяет тип переменной**, если она объявлена с инициализацией.
```typescript
let message = 'Привет, мир!'; // TS автоматически понимает, что тип `string`
message = 100; // Ошибка: Type 'number' is not assignable to type 'string'
```
Благодаря выводу типов, аннотации можно опускать, когда тип очевиден из значения.

#### 5. Интерфейсы: описываем форму объекта
Интерфейс (`interface`) — это способ описать **структуру объекта**, указав, какие свойства у него должны быть и каких они типов.
```typescript
// Объявляем "контракт" для объекта пользователя
interface User {
    id: number;
    name: string;
    email?: string; // Символ `?` делает свойство опциональным (необязательным)
}

// Создаём объект, соответствующий этому интерфейсу
const user: User = {
    id: 1,
    name: 'Мария'
    // Свойство `email` можно не указывать, так как оно опциональное
};
```

#### 6. Компиляция: от TypeScript к JavaScript
1.  Создайте файл `first.ts`:
    ```typescript
    interface Product {
      id: number;
      title: string;
      price: number;
    }

    const products: Product[] = [
      { id: 1, title: 'Ноутбук', price: 55000 },
      { id: 2, title: 'Мышь', price: 1500 }
    ];

    function getTotalPrice(items: Product[]): number {
      return items.reduce((sum, item) => sum + item.price, 0);
    }

    console.log(getTotalPrice(products));
    ```
2.  **Скомпилируйте** его с помощью `tsc`:
    ```bash
    tsc first.ts
    ```
    Рядом появится файл `first.js` — это чистый JavaScript, который можно запустить в Node.js или браузере.
3.  **Создайте конфигурационный файл** для управления компиляцией во всём проекте:
    ```bash
    tsc --init
    ```
    Эта команда создаст файл `tsconfig.json`, где можно задать версию JS для компиляции, строгость проверки типов и многое другое.
