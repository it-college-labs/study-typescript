### **📚 Конспект для студентов: Неделя 14 — Интерфейс и интеграция**

**Цель:** Создать интерфейс для вашего проекта и написать базовые тесты, чтобы убедиться в его работоспособности.

#### **1. Зачем это нужно?**

До этого момента ваше приложение было набором полезных функций (модулей). Интерфейс (CLI или веб-страница) делает эти функции доступными для пользователя. Тесты — это автоматические проверки, которые гарантируют, что ядро приложения работает так, как вы задумали, даже когда вы будете что-то в нём менять.

#### **2. Шаг 1: Создание интерфейса**

Ваша задача — создать «мост» между пользователем и бизнес-логикой.

**Вариант А: Консольный интерфейс (CLI)**

**Инструменты:** Встроенный модуль Node.js `readline` или библиотека `inquirer` (удобнее, но требует установки).

**Логика работы:**

Показать пользователю меню или запросить данные. Полученные данные преобразовать в нужный формат (например, строку в число). Вызвать метод вашего основного класса/модуля с этими данными. Показать результат пользователю.

**Пример структуры файла `src/cli.ts`:**

```typescript
// 1. Импортируем ядро приложения
import { FinanceManager } from './core/FinanceManager';

// 2. Создаём экземпляр
const app = new FinanceManager();

// 3. Взаимодействуем с пользователем (псевдокод для readline/inquirer)
function showMenu() {
  console.log('1. Добавить транзакцию');
  console.log('2. Показать баланс');
  // ... и т.д.
}

function handleChoice(choice: string) {
  if (choice === '1') {
    // ... запросить у пользователя сумму, категорию
    // 4. ВЫЗОВ ЛОГИКИ: Передать данные в ядро приложения
    app.addTransaction({ amount, category, date: new Date() });
    console.log('Транзакция добавлена!');
  }

  if (choice === '2') {
    // 4. ВЫЗОВ ЛОГИКИ: Получить данные из ядра
    const balance = app.getBalance();
    console.log(`Текущий баланс: ${balance}`);
  }
}
```

**Вариант Б: Простой веб-интерфейс (на Vite)**

**Инструменты:** Ваш проект на Vite уже готов к этому.

**Логика работы:**

Создать `index.html` с кнопками и полями ввода. В `src/main.ts` (или отдельном файле, например, `src/ui.ts`) написать код, который будет реагировать на клики. По клику получить данные из полей формы и передать их в ваш основной модуль. Отобразить результат на странице (например, в `div`).

#### **3. Шаг 2: Написание базовых тестов (Vitest)**

Тесты пишутся для модулей с логикой, а не для интерфейса.

**Что тестировать?** Ключевые функции, от которых зависит работа приложения: добавление данных, расчёт баланса, фильтрация, поиск.

**Структура теста:**

```typescript
// tests/FinanceManager.test.ts
import { describe, it, expect, beforeEach } from 'vitest';
import { FinanceManager } from '../src/core/FinanceManager';
import { Transaction } from '../src/types';

describe('FinanceManager', () => {
  let manager: FinanceManager;

  // beforeEach выполняется перед каждым тестом
  beforeEach(() => {
    manager = new FinanceManager(); // Чистый экземпляр для каждого теста
  });

  it('должен корректно добавлять транзакцию', () => {
    // 1. Подготовка: данные для теста
    const testTransaction: Omit<Transaction, 'id'> = {
      amount: 100,
      category: 'Food',
      date: new Date(),
    };

    // 2. Действие: вызываем тестируемый метод
    const result = manager.addTransaction(testTransaction);

    // 3. Проверка (Assert): проверяем, что результат соответствует ожиданиям
    expect(result.success).toBe(true);
    expect(manager.getTransactions()).toHaveLength(1);
  });

  it('должен корректно рассчитывать общий баланс', () => {
    // Подготовка: добавляем несколько тестовых транзакций
    manager.addTransaction({ amount: 100, category: 'Income', date: new Date() });
    manager.addTransaction({ amount: -50, category: 'Transport', date: new Date() });

    // Действие и Проверка
    expect(manager.getBalance()).toBe(50); // 100 + (-50) = 50
  });
});
```

#### **4. Контрольное задание К14.1**

**Задача:** Довести проект до состояния работающего прототипа с интерфейсом и базовыми тестами.

**Что нужно сделать:**

**Интерфейс:** Создать консольный (CLI) или простой веб-интерфейс для вашего проекта. Пользователь должен иметь возможность выполнить как минимум два ключевых действия (например, "добавить запись" и "посмотреть сводку").

**Интеграция:** Интерфейс должен быть неразрывно связан с ядром вашего приложения. Он должен импортировать ваши модули и вызывать их методы для выполнения действий.

**Тесты:** Написать 2-3 юнит-теста с использованием Vitest. Тесты должны проверять корректность работы основных функций вашего ядра (например, создание сущности, расчёт итогового значения, применение фильтра). Используйте `describe`, `it`, `expect`.

**Результат:** В вашем репозитории должны появиться новые файлы (например, `src/cli.ts` или `src/ui.ts` и папка `tests/`), а проект должен запускаться одной командой (например, `npm run dev` для веба или `npm start` для CLI).

**Критерии успеха:**

При запуске интерфейса программа работает без ошибок. Действия пользователя приводят к вызову методов ваших модулей и показу результата. Написанные тесты проходят (`npm run test`). Код интерфейса и тестов чистый и читаемый.
